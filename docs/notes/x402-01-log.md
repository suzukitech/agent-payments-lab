# x402-01 作業ログ（2026-10-15、時系列）

一次情報: https://github.com/x402-foundation/x402 の `typescript/packages/http/next/README.md`、`specs/x402-specification-v2.md`、`specs/transports-v2/http.md`（調査時に写しを保存）。

1. **環境**: Node は nvm に v22.17.0 のみ。そのまま使用（Next 16 の要件 >=20.9 を満たす）。pnpm が未導入だったので `npm i -g pnpm` → v12.11.2。gitleaks も未導入で `brew install gitleaks` → 8.30.1。pre-commit は `.githooks/pre-commit`（`gitleaks git --staged`）＋ `git config core.hooksPath .githooks`。gitleaks 8 系で `detect` は旧コマンド扱い、`git` サブコマンドが現行。
2. **ウォレット**: `scripts/gen-wallets.mjs`（viem 2.57.7）で売り手・買い手の2つを生成。鍵は `.env`（mode 600）のみ、stdout はアドレスだけ。売り手 0x621279161e951eB55195FB872e46CE47C6925506 / 買い手 0x62f9ECa8CC6332972705e7D5bEdc9f776CFdF673（テスト専用）。
3. **pnpm の予想外**: 初回 `pnpm install` が `ERR_PNPM_IGNORED_BUILDS`（esbuild, bufferutil, keccak, utf-8-validate のビルドスクリプト未承認）で終了コード非0。`pnpm approve-builds esbuild`、残りは `!` で拒否して解消。放置すると `pnpm dev` 実行前の自動 install も失敗扱いで警告が出る。また pnpm が `pnpm-workspace.yaml` に `minimumReleaseAgeExclude`（next@16.4.1, viem@2.57.7 等）を自動追記した（公開から日が浅いバージョンを供給網ポリシーで除外する機能。最新版を固定するとこの追記が入る）。
4. **peer 依存**: `@x402/next@2.28.0` の peer は `next >=16.2.6` と `@x402/paywall ^2.28.0`。後者も明示的に入れた。Next は latest の 16.4.1 を固定。`pnpm peers check` は @solana/kit, @wagmi/core, react 等の unmet peer を列挙するが、動作に影響は出なかった（paywall 経由の推移依存）。
5. **import 元の食い違い**: README は `import { paymentProxy, x402ResourceServer } from "@x402/next"`、クイックスタートは `@x402/core/server`。**両方試した。どちらも tsc 通過、実行時も 402 が返った**（`@x402/next` の index.d.ts が `x402ResourceServer` を `@x402/core/server` から re-export している）。採用は `@x402/core/server`（`HTTPFacilitatorClient` と同じ import に1本化できるため）。
6. **Next 16.4.1 の初回起動**: tsconfig を自動で書き換えた（`jsx: react-jsx`、`allowJs: true`、include に `.next/dev/types/**/*.ts`）。さらに `Generated AGENTS.md for AI agents` と出てアプリ直下に AGENTS.md が自動生成された（`agentRules: false` で無効化可）。
7. **402 の中身**: `/api/weather` は 402 + `payment-required` ヘッダー（base64 JSON）。**ボディは `{}` で空**（v2 は情報をヘッダーに置く）。デコード結果は amount "10000"、asset 0x036C…F7e、network eip155:84532、payTo 売り手アドレス、`maxTimeoutSeconds: 300`、`extra: {name: "USDC", version: "2"}`。`resource.mimeType` は空文字。`withX402` は `syncFacilitatorOnStart` 既定 true で初回リクエストに約 400ms（facilitator 同期）かかる。全出力は run.md。
8. **facilitator /supported**: `eip155:84532` には `exact` のほかに `upto`、`batch-settlement` もある。extensions に `eip2612GasSponsoring` 等。計画書の「exact あり」に加え、スキーム数が想定より多い。
9. **Faucet（未達）**: Claude in Chrome で https://portal.cdp.coinbase.com/products/faucet を開くと Coinbase のサインイン画面（email / passkey / Google / Apple）にリダイレクトされ、Chrome セッションは未ログイン。認証情報は入力しない方針なので停止。代替の https://faucet.circle.com は拡張側で「Permission denied for this action on this domain」（サイト権限未許可）となり操作不可。ETH faucet は試していない（どれもログインかユーザー側の権限設定が必要）。残高は viem で確認: 買い手・売り手とも ETH 0 / USDC 0。
10. **支払い試行**: `@x402/fetch` の `wrapFetchWithPaymentFromConfig(fetch, {schemes:[{network:"eip155:84532", client:new ExactEvmScheme(account)}]})` で `pnpm pay`（pay.ts）を実行。`ExactEvmScheme` は client 側は `@x402/evm` ルートから import できた（server 側は `@x402/evm/exact/server`）。結果は 402 のままで、再送後の `PAYMENT-REQUIRED` ヘッダーの `error` が `invalid_exact_evm_insufficient_balance`。つまり署名→再送→facilitator 検証までは動いていて、残高ゼロだけが原因。Next 側ログでも 2 回目の 402 は約 440ms（facilitator 往復）で、素の 402（数 ms）と区別できる。
11. **未取得**: 200、PAYMENT-RESPONSE、tx hash、Basescan のスクショ。faucet 後に `cd apps/paid-api && pnpm pay` で取れる。
